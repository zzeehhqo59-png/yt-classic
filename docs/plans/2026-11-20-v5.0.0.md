# YT Classic 5.0.0 Implementation Plan

**Goal:** Playlist page polish, local likes + "คุณ" page, Home empty state, 4.0.1 leftovers, and split WatchActivity (825 lines) into focused files.

**Architecture:** Flat package `com.bear.ytclassic` (existing pattern). Data access stays in small objects backed by `Db` (`Likes`, `Availability`, `PlayQueue`); UI files only call those objects. WatchActivity is split by responsibility: player overlay controls, header adapter, comments loader.

**Tech stack:** Kotlin, Android Views, ExoPlayer 2.19, NewPipeExtractor 0.27.1, SQLite, Coil 3. Pure logic covered by JUnit4 unit tests.

## Task 2 — Data: likes, availability, play queue (+ unit tests)
- `Db` v4: tables `likes(url PK, video cols, value INT, at INT)` and `unavailable(url PK, kind INT, at INT)`.
- `Likes` object: `state(url)`, `set(v, value)`, `liked()`, `count()`.
- `Availability`: `kindFromTitle(title)`, `kindFromError(...)`, `mark(url, kind)`, `kind(url)`, `apply(list)`.
- `PlayQueue`: `start(list, index)`, `onOpen(url)`, `nextPlayable()`, pure `nextPlayableIndex(list, from)`.
- `Fmt.channelLabel(name, url)` → "@handle" when url has `/@`.
- Tests (JUnit4, `app/src/test`): title→kind, error→kind, nextPlayableIndex skips unavailable, channelLabel.
